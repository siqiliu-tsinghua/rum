## 第一层：主线本身

审计的 7 项发现里，2 项已修、1 项部分处理、4 项未动；3 条威胁模型批评都还没回应。

| 项 | 级别 | 状态 |
| --- | --- | --- |
| 内存上限采样有间隙，可以大幅超额 | HIGH | 已修（brief 513–515） |
| 等待输入时超时被丢掉 | MEDIUM | 已修（brief 510–511） |
| 符号表进程级共享、只增不减、内存上限看不见 | HIGH | 部分处理：一种方案已被否掉，配额方案搁置。根源在快照格式，已裁定改成二进制，排在保留线之后 |

| `$Context` 跨请求泄漏 | LOW | 未动 |
| `restore_from_bytes` 的后果没写进文档 | LOW | 未动 |
| 威胁模型批评：哪些状态按请求、哪些按会话；Jupyter 内核的权限；RSS 缺口 | 批评 × 3 | 都还没回应 |

修审计问题时又引出了一些事：

- **已完成**：会话内存遍历从 34 个字段补到 52 个；armed 上限改成维护一个总量，不再每次重新遍历。
- **未完成**：165 个内置函数的 `Incremental` 声明没有兑现；调用缓存按条数而不是按字节限制；一个原因不明的 1 668 字节；文档和代码不一致的两三处。

## 第二层：保留线（暂停在 E0）

保留线是剩余工作量最大的一层，基本还没开始。它要解决的问题是：Rust
内部的累加器可以绕过内存上限。设计见
[`retention-closure-design.md`](./retention-closure-design.md)。

**已完成**：设计、检查工具（lint）、租约协议，以及第一个区域（option）的认证，覆盖 2 个函数体（C01、C02）。

**剩下的，按顺序**：

1. E0：4 处值的拷贝逃出了区域。
2. H：让 lint 能对指定的生产代码函数体运行。
3. 用 H 把 101 条还没定性的行定下来，重算排名。
4. K/A：精确契约和窄准入。
5. 7 种新协议接口，各自在用到它的区域之前做。
6. **13 个区域，覆盖 195 处声明**，按收益排序。按 option 区域的经验，每个区域大约 5–6 个 brief：设计、本地读取、租约构造、累加器与交接、消除未武装时的开销、认证。

## 第三层：挂起续接分支（正在做）

分支大部分已完成，剩下的主要是 G13 余下的 75 步和 E2。分支于 2026-09-28
插入，要解决的是：内置函数在工作中途等待输入后，必须恢复到那项工作里。

**已完成**：

- guest 加载、批处理边界、所有前端（REPL、CLI、Jupyter）；
- G1–G12，共 86 处丢失的续接；
- E1：覆盖整个目录的一致性检查。

**G13**（续接状态改成类型化，不再以表达式的形式在帧之间传递）共 78 步，分步方案见
[`brief-606`](./codex/brief-606-g13-design-round-5-type-then-flip.md)：

| 部分 | 步数 | 状态 |
| --- | --- | --- |
| S1 休眠 API | 1 | 已完成（`777c61cc`） |
| S2 兼容驱动 | 1 | 已完成（`cb09bfde`） |
| S3 求值、参数准备与分派 | 1 | 已完成（`1a228f4b`，派发 9 次） |
| S4–S54 按家族类型化 | 51 | 未开始 |
| F1–F23 每个旧类型一次切换 | 23 | 未开始 |
| R 移除旧机制 | 1 | 未开始 |

换个角度看：生产代码里有 607 个旧式帧实现，S3 完成后只有 12 个改成了类型化，约
2%。G13 之后是 E2：给可能挂起的调用一个没有 `Try` 的结果类型。

S1–S3 每步都派发了多次（S3 共 9 次），但其中不少是一次性代价：令牌改成只有一条路线；分析器学会读新宏，各视图对齐；所有权台账学会了 blanket 擦除；还修掉了 S1 里潜伏的 finalizer 二次装箱。后面的步骤应该会顺一些，但不能保证。

## 之后的顺序

内层做完才回到外层，一条线开了就做完：

1. 挂起续接分支收尾（G13 余下 75 步、E2），然后处理排在它后面的 Q1–Q4：
    1. Q1：从内核到宿主保持一条有序的打印与消息输出；
    2. Q2：空的惰性 `First` 重复发出 `First::nofirst`；
    3. Q3：gensym 清理漏掉 Rust 局部值，按类设计；
    4. Q4：`ReleaseHold` 按 WL 语义修正。
2. 保留线从 E0 恢复。
3. 二进制快照格式（符号表泄漏的根源）。
4. 主线剩下的审计项，以及威胁模型的 3 条批评。
5. 全部做完才考虑 v0.3.0。
